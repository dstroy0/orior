# The query protocol table

**Purpose:** The query protocol step by step: what each step asks, the algebra it holds to, what it does, what it wants, what was tried and what it gave, its status, and the next move.
**Scope:** every step between a question put to a target and a branch consuming the answer: the ask, the unbound and bound passes, the gate, the order of asks, the contention read, cross-branch comparison and the record. Its inputs are the entries of `Lstar.klq`, the bridge between languages, and of each language's `.klm`, and every step gives back entries of them. The protocol's form and its mnemonics are in [gnascor.md](../../../src/cu/transpiler/gnascor.md), and its open work is in this table: each step's next move, the protocol and its open work after the algebra, and the run as a database after them. Statuses follow [README.md](../engine/README.md), and every status names the run behind it.

## The rule the protocol is held to

**Gate, then rank. Never one score.** A relation holds or it does not, and that answer carries no noise. A cost is measured and every cost carries noise. The gate decides which candidates are admissible and the rank orders whatever survives, and the two are never added together. Kept apart, a noisy cost can cost speed and can never cost correctness. The engine already holds this rule in its own descent: survival is a conjunction, order cannot change a conjunction, and a planner that steers badly costs speed and never a wrong survivor (`src/cu/engine/nbody/orior/orior_descent.h`).

**Steer on what is known to be true.** Every relation the ladder holds is arithmetic every system that computes agrees about, and the host computes it. The gate is planned against that ground truth on the host, and a target is asked only the cases the plan placed.

## The inputs

**The inputs are entries.** `Lstar.klq` is keyed by the schema's form names, which are gnascor's and no target's. For each key it holds the pairs of forms whose sameness the text leaves open, the cases put to them, and the verdict: closed as two operations with the case that witnessed it, or open with its count of cases alike. A language's `.klm`, `cu.klm` or `sass.klm`, keys that language's names to the bridge, each entry naming its relation on its own line. An address is a key of the bridge read through a language's map, and a map from one language to another is read through the bridge, `cu.klm` to `Lstar.klq` to `sass.klm`. `klq_write` (`src/cu/transpiler/lstar/protocol`, run by `orior protocol write bridge`) writes `Lstar.klq` and each given language's `.klm` beside the rulesets, the forms of each line in `src/cu/types/file_defs/klq` and `klm`, and no step reads one.

**A reading of a part of a set is 1, 0 or gray.** No set of entries is known to be whole. A witnessed relation that holds of a part holds of every set holding that part, and its 1 is a verdict; where it does not hold, a file added can make it hold, and the reading is gray. A relation of absence reads the other way: a name given is given in every set holding it, and that 0 is a verdict, and a name not given is gray. gray is gnascor's state: no answer, and not void, which is an answer of no (P1, P10).

## The algebra of the protocol

Every line is exact. A cost is a reading and carries a spread; a relation is arithmetic and carries none.

Every line takes the entries of the bridge as its inputs (The inputs, above). An address is a key σ of `Lstar.klq`, M_L is language L's `.klm`, which gives each name of L its key, and K(σ) is the key's cases. A candidate is a form a language's map or the part's machine file gives for σ, and what a step finds is written back to σ.

### P1. The ask and its bound (Q1, Q2, Q3)

An ask a = (address, qualifier) returns, unbound, its cost t(a). Bound by β it returns one bit:

  bit(a) = [qualifier holds] · [t(a) ≤ β]

A missing address, a false qualifier, a timeout, an error and too many cycles all read 0. What tells them apart is the baseline, the spread of unbound costs, and the bound is read off it (Q2) and never written by hand. A run that never returns is apart from all of these, a reset and not a reading, and P9 holds it.

Over the bridge an ask is a = (σ, L, r): a key, the language whose map it is read through, and a relation r of the entries M_L gives at σ. A relation of the text carries no cost and no bound enters it. On a part E of a set of entries:

  read(a, E) = 1 where r is witnessed and r(E); 0 where r is a relation of absence and not r(E); gray otherwise

A relation the part answers, forms f and g on the cases K(σ), reads as P1 reads each answer, its kind with it, so that a refusal from one where the other answers is a case apart:

  read(a, K) = 1 where f(k) ≠ g(k) for some k ∈ K; gray where f(k) = g(k) for every k ∈ K, and |K| its reading

Neither ever reads 0: no answer of the part confirms two names one operation (P10).

### P2. The gate (Q4)

A relation r is held on cases K = {k_1, …, k_m}. A candidate c survives when

  c(k) = r(k) for every k ∈ K

- **The survivors are a conjunction.** S = {c : c(k) = r(k) for every k ∈ K} does not depend on the order of K, and no order of the cases changes which candidates survive.
- **The order is the price.** Putting K in order π costs Σ_c f_π(c) evaluations, f_π(c) the place of the first case c fails (m for a survivor). The descent puts first the case the most remaining candidates fail.
- **No cost enters S.** A candidate that fails a case is wrong on every part, and no part is asked about it.
- **Proved** (Q4): the descent's survivors equal `chain_build`'s on every relation the ladder holds.
- **Over the bridge.** With C(σ) the candidates of a key and r_σ its relation, S(σ) = {c ∈ C(σ) : c(k) = r_σ(k) for every k ∈ K(σ)}, written back to σ. The reader's gate over a set of files is the same conjunction: a set E is refused where R(E) for a witnessed absurd relation R, and is then refused in every set holding it. No order of the files or of their lines changes which sets are refused: no entry waits on another. A set not refused stands open, as a survivor of the gate does.

### P3. The order of asks (Q5)

For a chain of n links, n + 1 a power of two, ask r covers link c where (r + 1) & (c + 1) has an odd count of ones: the rows of a Hadamard matrix of order n + 1 with its first row and column dropped, read as 0 and 1. With b_r the cost ask r returns and x the per-link costs:

  (n + 1)·x = 4·Sᵀb − 2·(Σb)·1

- Every link is covered by (n + 1)/2 asks and any two links share (n + 1)/4, and that is the identity 4·SᵀS − (n + 1)·J = (n + 1)·I, with Σb = ((n + 1)/2)·Σx (**proved** here for n = 3, 7, 15, 31 and 63). The solve is integer adds and one division by a power of two (**proved**, Q5).
- Against one ask a link, the gain is (n + 1)/(2·√n), which √(n + 1)/2 approaches as n grows: each x_c takes every b_r at a weight of ±2/(n + 1), and its squared spread is 4·n/(n + 1)² of one ask's (derived; **measured** 1.09, 2.07 and 8.16 at 3, 15 and 255 links against 1.15, 2.07 and 8.02, Q5).
- **Over the bridge.** The n links are keys σ_1, …, σ_n: a chain written in language L, each of its lines taken to its key by M_L. x_c is kept at σ_c, and two chains written in two languages compare at the keys they share (Q8).

### P4. Contention (Q7)

Each of N sweep asks covers a count u of links, and y is what is left of its cost once the known order's links are taken out. The model is y = α + γ·u + δ·u² + noise, and contention is δ > 0. With every sum centered and scaled by N,

  C_pq = N·Σpq − Σp·Σq

and the count taken out of the square s = u² and of the leftover y,

  P_ss = C_uu·C_ss − C_us²,  P_sy = C_uu·C_sy − C_us·C_uy,  P_yy = C_uu·C_yy − C_uy²

the square's slope P_sy/P_ss has squared spread (P_yy − P_sy²/P_ss)/((N − 3)·P_ss), with N − 3 left over past the three unknowns. The slope stands above twice its spread exactly when

  P_sy²·(N + 1) > 4·P_yy·P_ss

which is every term an exact integer and no division (`ask_links_read`, `src/cu/transpiler/lstar/protocol/order/ask_order.c`). Fewer than three counts covered leaves P_ss = 0 and nothing to read; P_sy ≤ 0 reads as adding.

Over the bridge the u links an ask covers are keys, and a contention read is kept with the keys of the asks it was read over.

### P5. One ask, many answers (Q15)

A set of checks each failing with share p is asked as one bit, 1 where every check holds and the set halved on a 0. Past p = (3 − √5)/2, about 0.382, asking one check at a time costs no more than any scheme that asks a set as one bit (cited from knowledge: P. Ungar, "The cutoff point for group testing", Comm. Pure Appl. Math. 13 (1960) 49–54). The channel's answer of 128 bits carries one bit a check, which pays on every relation (**measured**, Q15).

Over the bridge a check is a pair (f, g) at a key and one case k, and its bit is [f(k) ≠ g(k)]. A pair closed by k is closed on every K′ holding k (P10) and is not asked again: the checks still put at a key are its open pairs, each against the cases not yet asked of it.

### P6. The rank, read against its own spread (Q16, Q17)

Each survivor c is run T times and its runs t_c,1, …, t_c,T taken. A run is lengthened by whatever else the host does and never shortened by it:

  m_c = min_j t_c,j,  s_c = max_j t_c,j − m_c,  s = max_c s_c

With the survivors ordered by m, c_1 the least and c_2 the next, c_1 is the part's choice where

  m_c2 − m_c1 > s

and otherwise the survivors are one cost and the ruleset keeps its form. The gate (P2) decides which candidates hold and this rule orders the survivors, and the two are never added together.

Over the bridge the survivors are S(σ), and the rank is kept at σ with the part and the size it was read on (Q10): the language's `.klm` gives σ the form c_1 where m_c2 − m_c1 > s, and otherwise keeps its form.

- **Measured** (Q16): 8 survivors in `loop_back_if`'s place on sm_86, m_c2 − m_c1 = 0.0525 ns a turn against s = 0.9260. The least of one run, `BRA.CONV`, is not the least of the next, `BRA` with a number, as a difference inside the spread gives.
- **Measured** (Q2, the monolith): 15 precepts alone, a million steps a chain, 16 runs. The eleven single-instruction precepts sit within 0.006 cycles of each other in m against s = 2.22, one cost. The two deltas that stand are 0 to 4.05, no instruction against one, and 4.06 to 8.05, one against two. `monolith_run` reads a delta inside s as dual or gray and one past it as lead (gnascor).

### P7. A form asked of the part (Q16)

The slot is `loop_back_if loop where`. The question is a body the slot closes:

  R7 ← 0, R0 ← N;  turn: R7 ← R7 + 1, R0 ← R0 − 1, P0 ← [R0 ≠ 0];  then the candidate, guarded by P0

- A candidate that takes the way back on P0 runs N turns and answers R7 = N.
- A candidate that falls through runs one turn and answers 1.
- N = 2 separates the two, 2 against 1. The counts after it, 1, 3, 5 and 64, hold the answer to N: a form that came back a fixed number of times answers that number and not N.
- The candidates are every form in the part's machine file, with every register made R8 and every uniform one UR8, which the body does not keep, a predicate made P0 (PT, RZ and URZ kept), a label the body's and a number the distance back to it, 0x40 bytes over four instructions. Nothing decides beforehand which forms jump.
- A survivor is walked: `sass_loop_walk` reads its encoding back through the forms of the machine file and checks it as a loop's way back, the flag, the distance, and every register the body keeps left as it was.
- **Proved** (Q16): 8 of the 2927 forms answer every count, every one a `BRA`, and the walk agrees with all 8. No form answers N = 2 without answering every count.
- **Over the bridge** the slot is the key `loop_back_if`, its cases the counts, and the 8 forms that answer every count are S(σ), kept at it.

### P8. Held against NVIDIA's compiler (Q17)

For a program p, C(p) is its text through `c.krs` and E(p) its lane through `sass.krs`. V(p) is what NVIDIA's compiler writes for C(p) and h(p) what the host oracle answers.

  E(p)(k) = V(p)(k) = h(p)(k) on every lane k

is the gate, and the rank is P6 between E(p) and V(p), with |E(p)| and |V(p)| their instruction counts as a second reading. E(p) holds NVIDIA's line where m_E(p) − m_V(p) ≤ s.

- Where E(p) costs more, V(p)'s instructions over that part name forms, each in a slot. Each slot is a question for Q16: the forms of the machine file in that slot, the cases of the slot, and the survivors ranked by P6. NVIDIA's listing names the question and the part answers it.
- The loop closes when E(p) holds NVIDIA's line on every program p, and every form in every ruleset was answered by the part.
- **Over the bridge** E(p) is read through `Lstar.klq`: each line of p, written in cu's names, is taken to its key by M_cu and from the key to sass's names by M_sass, E(p) = M_sass⁻¹ ∘ M_cu applied to p. A line whose key the map breaks, collapses or gives as another kind cannot be read through as it stands, and those are the map's witnessed relations (P10). A key sass gives no name for is open, and E(p) is gray at that line and not refused. **Measured** (Q19), the map read directly between cu's set and sass's with no `.klm` written: 32 witnessed relations each way, 0 open.
- **Built:** E(p) for the 8 record programs the host oracle runs, 16 lane programs, every instruction assembled against sm_86's machine file (Q17). **Measured:** V(p) for the monolith's 18 blocks, one base precept each, held against our reader, our assembler and E(p) instruction by instruction (`monolith_differences.md`, Q17). **Theory:** the rest.

### P9. The part's own bound (Q1, Q16, Q17)

P1 counts a timeout among the readings of 0, which holds only where the run returns. A run that never returns is a reading apart: the part's display watchdog ends it with a reset, and across a run of asks that reset can hold a kernel's own watchdog past its bound and stop the host with a DPC_WATCHDOG_VIOLATION.

A body runs without end only where control reaches a line it has passed and the way back never closes. Four contexts reach it:

- A turned bit makes the instruction a branch to itself or a line before it. An isolated instruction turned this way is most often an illegal encoding the part refuses as a clean 0; a turned branch is not refused.
- The body holds a read it waits on, a register or a word read again until it carries a mark, and the turned bit closes the wait: the register the read names, the value it is held against, or the step that moves it. loop_back_if (P7) is such a body, its way back taken on P0 = [R0 ≠ 0]; a bit that stalls the step or frees the branch leaves it turning without end.
- A barrier every lane is waited at, where a turned bit sends a lane down a path that never reaches it, and the lanes that waited do not return.
- The scheduler word waits on a scoreboard barrier a late result sets and that result never clears it. Above the operation the encoding holds a stall, a write and a read barrier and a wait over six barriers, none of it printed. A result ready after a fixed count carries that count as its stall; a result that comes back late, a load or a memory read, sets a barrier instead, and whatever reads the register it writes waits on that barrier. A barrier no instruction sets is at rest and a wait on it resolves at once; a wait on a barrier whose setter a turned bit sends a lane past never resolves, and the lane does not return.

The local absurdity, an isolated instruction turned illegal, the part refuses and the ask reads. The waited read is where a turned bit writes a lawful instruction that breaks the wait, and a lawful instruction runs where an illegal one refuses. An ask that holds a waited read carries its own bound in the body, a turn count past which no turned bit runs, and keeps that count in registers the turned bits do not reach: loop_back_if holds its candidate off the counter R0, every register in the candidate made R8. The host's patience and the display watchdog are a reset, never the bound.

An ask that turns an instruction's bits is checked before it is put. The opcode, the low word's bits 0 to 11, names the operation, and a turned instruction is put to the part only where its key holds forms in the machine file and no control transfer or wait among them. Such an instruction falls through whatever its other bits hold. A turn past the key leaves the operation as it was. Every other turn is marked skipped and run on nothing, which closes the first context above for every key the machine file holds (`interface_sass_probe_fields.c`, Q17).

The scheduler word is set once for a run and no turned bit reaches it. The assembler writes every instruction to wait on all six barriers and to stall the soonest its operation's result is read, the longest where the krs measures no count, and to set a write barrier where the operation's result comes back late and a read barrier where it is a store (`sass_control_safe`). `cubin_safe` holds every instruction it reads to that stall. Which those are is the operation's schedule, a property of the operation the krs holds beside the scheduler's fields (`sass_operation_schedule`, `sass_machine`), and not of the one encoding the machine file first saw it with: that encoding sets no write barrier on `LDS` and no read barrier on any store. A turned bit lies at 0 to 104 and leaves 105 and up as they were: the safe word stands on every flip, and no flip opens a path around a barrier's setter. This closes the scheduler context for a flip probe, where the body is straight-line and every barrier set is cleared by the instruction that set it.

- **Measured** over the tree's CUDA sources built by NVIDIA's compiler for sm_86 (`monolith_scheduler.md`, 72 cubins, 96976 instructions, each named by our reader and its bits 105 to 127 read through the krs's fields, no listing read): NVIDIA gives a write barrier at every place to `LDG`, `LDS.64`, `LDS.128`, `S2R`, `S2UR`, `F2I`, `I2F` and `ATOMG`, and at most places to `LDS`, `MUFU.RCP` and `F2I.FTZ`; to 94 other operations at none. A barrier counts its producers, and a wait on it holds until every one of them is back: of 1716 first reads of a late result with its own barrier, a wait on that barrier stands before all 1716, at the reader or at an instruction before it. A late result NVIDIA gives no barrier is held behind another of the same operation out of the same unit: 20 first reads, 16 of `LDS` and 4 of `MUFU.RCP`, stand behind a wait on a later one's barrier, the results coming back in the order they were put; 6 of `MUFU.RCP` stand behind a wait on an earlier one's barrier and at least 16 cycles past it. No first read of a late result stands behind no wait. Every `STG`, `STL`, `ST`, `STS` and `RED` takes a read barrier at most or every place. A fixed result is first read no sooner than 4 cycles on all 21 integer operations timed over 67443 reads, 5 on `IMAD.U32`, `IMAD.WIDE` and `IMAD.WIDE.U32.X`, and 6 on `CS2R`. The safe word waits on all six barriers at every instruction, which holds every one of these. Six barriers on every part from SM75 on, each a count its producers raise and a wait drains, and loads that keep their order sharing one barrier, are as the published reverse engineering of the scheduling word gives them (cited from knowledge: the ptxas execution model at gh.evko.io/crucible-notes, and the control codes of the maxas assembler, github.com/NervanaSystems/maxas/wiki/Control-Codes).
- **Measured** on the part: a barrier set by an operation whose result is back in a measured count is never released, and a wait on it does not return. `sass_control_safe` sets none on such an operation, and `cubin_safe` refuses one that does (its rule 5). A pair a link writes and the next link loads through, read too soon, is read before it is back, and the load ends on an illegal address: the early read is legal, and the address it reads is none of the question's. Written by `IMAD.WIDE.U32`, the part refuses the load at stalls 1 and 2 and answers it from 3; written last by `IADD3.X` (`wide_add`) or `MOV` (`wide_pack`), at 1 to 4 and from 5 (`pairs stall`, every load the stick holds, 18 probes a writer). Every other pair read too soon answers apart and is never refused.

The gate (`cubin_safe`) reads a turn by its key, and a straight key is not a legal instruction: the key names the operation at bits 0 to 11, and the operation's own layout can refuse what the other bits hold. Where the machine file holds no form of a key, the gate passes a turn of it on the key alone, and an encoding only the operation's layout refuses falls through. Before a round reaches the part, each question is read against NVIDIA's disassembler off the part (`orior protocol cross`, `src/cu/transpiler/vendor_bin_layouts/nvidia`): the carrier (`cubin_run`) writes each container with the part taken out, the disassembler reads it back, and a question it calls an illegal instruction, or a control transfer at the slot, is held off the part on the live run however the gate read it. The disassembler names no operation and nothing it says enters a form: the held list is only the exact encodings not to ask. A round's forms are read in two passes, the turns of each form and then the register-runs its turns find, and neither reaches the part before the disassembler has read it (`orior protocol learn`). Each round is read as it is made, a round made from the answers before it as much as the first, and a question held only for a register past the count its kernel allots is put again with the count that clears it, which changes how it is put and not what it asks; each hold and each count given is a line of the teacher's trace (`run_channel.h`). **Measured** on the RTX 3070, sm_86: of the add's 93 turns one is held, the flip of bit 91, an illegal encoding the gate's key passed; the part learns the form with that one held and no reset (`khw_write`, kept in `sm_86.khw`).

### P10. Absurdity from a part of a set (Q19)

A set of files E holds entries, and a relation R over entries holds of E or does not. R is witnessed where

  R(E) ⇒ R(E′) for every E′ ⊇ E

and it is then a verdict on any part of a set that holds the entries it names. A relation of absence, that no entry of E gives the name x, holds of E and of no E′ holding a file that gives x. Read on a part of a set it is open: no read of a part decides it, and no set is known to be whole.

- **Witnessed:** a name given twice, the same text under two names, a construct that is one form renamed, names one word apart with texts the same but for their modifiers, a form opening another's literal operands, a construct that reaches itself, a parameter never written, a place no parameter takes, a form with no text, a register's numeric name where a fixed register gives it a name, a row given twice, a name the schema does not name, and a form taking another count of parameters than the schema says. Each is witnessed by the one or two entries it names. A classification's counts and classes are held within the file they are written in, which is read whole, and that file witnesses them.
- **Open:** a construct's line writing a name no entry gives, and a name of the schema no entry gives.
- **Asked of the part:** forms f and g put on cases K are two operations where f(k) ≠ g(k) for some k ∈ K, and that k witnesses it on every K′ ⊇ K. Where f(k) = g(k) for every k ∈ K, their sameness is a relation of absence over the cases, open on every K short of every case, and |K| is its reading, as the survivor count is (Q11). The text witnesses sameness and the part witnesses difference: no answer of the part confirms two names one operation, and no difference of texts confirms two operations.
- **The reading of a part:** a witnessed R reads 1 where R(E) and gray where not; a relation of absence reads 0 where the name is given and gray where it is not. A set known whole would leave no gray, and no set is known whole.
- **Maps:** the map from language L to L′ holds, for each name L gives, whether it is one text with another name in L and two in L′ (breaks), two texts in L and one in L′ (collapses), or given in L′ as another kind of form, nop, err or construct (kind). Each is witnessed by the entries it names. A name L′ does not give is open (absent). **Measured** (Q19): 32 witnessed and 0 open each way between cu's set and sass's.
- **The bridge:** each language is mapped once, to `Lstar.klq`, and a map between two languages is read through it, M_L′⁻¹ ∘ M_L: n languages take n maps, where read pairwise they take n·(n − 1). **Measured** (`orior protocol write bridge`, `cu.klm` and `sass.klm` with 151 keys each): every name of the 41 the map read directly between cu's set and sass's names is found on the two maps through the bridge, each way. Through the bridge 6 names more each way are one text with another on one side and two on the other, where the other side gives one of the two as another kind, which the direct map reads as kind alone.

### P11. The ruleset, derived ask by ask (Q4, Q11, Q18, Q19)

A ruleset gives each slot σ one form, and each fact of the part one number. Both are derived by putting relations to the part whose right side the host computes, one case at a time, each answer read as P1 reads it. No value is written by hand: a number enters as the answer of the host to a case or as the part's answer to an ask, and every walk over a number runs until the part says no.

**The ask.** A form f is put on a case k beside the answer of the host, h(k):

  `f(k) = h(k) ?`

The part gives one of four answers. Alike, where f(k) = h(k). Apart, where it gives another word. Refused, where it ends the run as an illegal instruction, an illegal address or a launch out of resources. Nothing, where no answer comes back. Alike is truthy and the other three are falsy.

A case on which the C of the host traps or is undefined carries no h(k): a divisor of 0, the least value over −1, and a shift by the width or past it. The part's answer to such a case is read and kept, and gates nothing (`refused_<n>` in the host program `klq_identity` writes). Each is judged in the operand's own type: a `signed char` divisor put 0x100 is a divisor of 0.

**What the host computes.** Every integer question a slice holds, every task of register pressure, and every question the engine writes a chain for: each chain the part is asked is held to h on every case.

**The cases.** Each operand is put through 18 values: 0, 1, 2, 3, and the edges of every width, 0x7F, 0x80, 0xFF, 0x100, 0x7FFF, 0x8000, 0xFFFF, 0x7FFFFFFF, 0x80000000, 0xFFFFFFFF, 0x100000000 and the three edges of 64 bits. With a third operand of two values, a two-operand form meets 18 · 18 · 2 = 648 cases.

The steps run in order, and each takes what the steps before it found.

**Step 1. The width (Q18).** Before any value is given a register:

  `read(put(0xFF)) = 0xFF ?`  `read(put(0xFFFF)) = 0xFFFF ?`  `read(put(0xFFFFFFFF)) = 0xFFFFFFFF ?`  `read(put(0x1FFFFFFFF)) = 0x1FFFFFFFF ?`

The width w is the widest put that comes back whole, and the next one comes back cut at w. Once add stands (Step 2), two more asks must agree with it: x doubled from 1, `x ← x + x`, reads 0 at the w-th doubling and at no doubling before it, and `0xFFFFFFFF + 1 = 0 ?` is alike where w = 32. Where the three do not agree, nothing past this step is asked. **Theory.**

**Step 2. Add, by the descent (P2).** The candidates are every form the machine file holds in a two-operand slot, operands filled by their kinds. The descent puts first the case the most candidates fail. Five candidates and add, on four cases:

| case | h = add | or | xor | and | take | mul |
|---|---|---|---|---|---|---|
| `1, 1 → 2 ?` | 2 | 1 | 0 | 1 | 0 | 1 |
| `0, 1 → 1 ?` | 1 | 1 | 1 | 0 | 0xFFFFFFFF | 0 |
| `1, 0 → 1 ?` | 1 | 1 | 1 | 0 | 1 | 0 |
| `0xFFFFFFFF, 1 → 0 ?` | 0 | 0xFFFFFFFF | 0xFFFFFFFE | 1 | 0xFFFFFFFE | 0xFFFFFFFF |

- `1, 1 → 2 ?` fails all five, and it is placed first: the carry out of the low bit is what add holds and no bitwise form holds.
- `0, 1 → 1 ?` and `1, 0 → 1 ?` fail a form that drops an operand.
- `0xFFFFFFFF, 1 → 0 ?` fails a form that saturates at the top, or carries into a 33rd bit.
- On the ladder's candidates the descent places one or two cases a relation, and every impostor fails at the first or second (**proved**, Q4). The survivors are S(add), and their count is a reading (Q11).
- At 2w a value is two words, and a form of 2w is a pair of forms of w. `0xFFFFFFFF, 1 → 0x100000000 ?` fails a pair whose two words are added apart (0): the high word takes the carry out of the low.

**Step 3. Take.** `1, 1 → 0 ?`, `0, 1 → 0xFFFFFFFF ?`, `1, 0 → 1 ?`.

- `1, 1 → 0 ?` fails add (2) and or (1); xor answers 0 and stands.
- `0, 1 → 0xFFFFFFFF ?` fails xor and or (1), a form that takes the operands swapped (1), and one that saturates at 0 (0).
- f(0, 1) ≠ f(1, 0) witnesses that the form does not commute, which add and every bitwise form do.
- At 2w, `0x100000000, 1 → 0xFFFFFFFF ?` fails a pair whose two words are taken apart (0x1FFFFFFFF): the high word takes the borrow out of the low.
- −a is 0 − a in a's type, put to take as `0, a`, and no form of its own is asked for it.

**Step 4. Divide.** `0, 1 → 0 ?`, `1, 1 → 1 ?`, `3, 2 → 1 ?`, `0xFFFFFFFF, 2 → ?`, `1, 0 → ?`.

- `3, 2 → 1 ?` fails a form that rounds (2).
- `0xFFFFFFFF, 2` is 0 signed, −1 over 2 cut toward 0, and 0x7FFFFFFF unsigned; a form that rounds down gives 0xFFFFFFFF. One case separates the three.
- `1, 0` and `0x80000000, 0xFFFFFFFF` signed carry no h(k). The part's word on each is kept at the key with the form that gave it. Two forms that give two words there are two operations (P10), and since C leaves the case undefined, either holds as the slot's form.

**Step 5. Shift.** `1, 31 → 0x80000000 ?`, `0x80000000, 31 → 1 ?` right, `1, 32 → ?`.

- `0x80000000, 31` right is 1 unsigned and 0xFFFFFFFF signed, which separates the logical shift from the arithmetic one.
- `1, 32` carries no h(k). A form that clamps answers 0, and a form that wraps answers 1. The case keeps the two apart as operations without gating either (Q17: NVIDIA's `.W` wraps, where the precept wraps too).
- Every case with an h(k) has a count under w, and its low word holds the count. A count held in two words is put as its low word, and every case with an h(k) answers the same.
- At 2w, `0x100000000, 1 → 0x80000000 ?` right fails a pair whose two words are shifted apart (0): the low word takes the bits the high word lets go.

**Step 6. Compare, and the select that reads it.** `0, 1 → 1 ?`, `1, 0 → 0 ?`, `1, 1 → 0 ?`, `0xFFFFFFFF, 0 → ?` for less-than.

- `1, 1 → 0 ?` fails less-or-equal (1).
- `0xFFFFFFFF, 0` is 1 signed and 0 unsigned.
- A test and the select that reads it are one word, asked as one (Q19).
- A bool is a relation and no narrowing: `(bool)v` is [v ≠ 0] over the whole of v. `0x100000000 → 1 ?` fails a flag of the low word alone (0), which a byte or a halfword is right to read.
- A flag read as a word and tested against 0 is the flag: [select(p, 1, 0) ≠ 0] = p on every case. The round trip is a cost to rank (P6) and never a gate, and a reader that does not hold it reads each conditional nested in another again for every reading of the one around it.

**Measured**, Steps 2 to 6 on sm_86: the engine's chain for every question the host computes, 441 of them, answers alike on all 648 cases and none apart. The 64-bit add, take, bitwise forms, not, negation and both shifts right are among them, each in the two words of NVIDIA's listing, every comparison glued to a second test by `&&` or `||`, and every select over a bool.

**Step 7. Two forms, one slot (P10).** Forms f and g in one slot are put on K. The first k with f(k) ≠ g(k) closes the pair as two operations, and k is kept at the key as its witness. A pair alike on every k ∈ K stays gray, with |K| its reading. A case closes a pair once, and a closed pair is not asked again (P5).

**Step 8. The bound in place of a counterexample.** An L* learner asks whether a conjecture is the machine and is given a case apart when it is not. The part gives no such case: K stands in for it, as a test suite does ([learning_a_ruleset.md](../../thought_experiments/engine/learning_a_ruleset.md)). An operation on words holds no state, and so the bound is on cases and not on states: a form is exact on K and gray past it. A two-operand form of 32 bits has 2^64 cases, and a form apart on a case outside K is found only by adding that case to K. **Measured** at 16 bits: 55 forms on all 65,536 cases against the integers of the host ([learning_a_ruleset.md](../../thought_experiments/engine/learning_a_ruleset.md), Status).

**Where the questions are bounded.** Each step asks only what the step before it can hold, and each bound is a place the ruleset is gray. Read off the stick's 1016 questions:

- **The cases.** An operand meets 18 values and no other. Between 0x100000000 and 0x7FFFFFFFFFFFFFFF none is put, and a form apart only there is found by no case (Step 8).
- **The C of the host.** A case it traps on or leaves undefined carries no h(k), and the part's answer there is held to nothing (Steps 4 and 5).
- **The types of the host.** The host computes integers alone: 436 questions, and float and double, 398 of the 1016, are asked of nothing. No form of a floating slot is derived.
- **The reading of the engine.** A question the engine cannot write through cu.krs is asked of nothing: 166 besides the floating ones. 35 have no reading, 33 of them a quotient or a remainder, which sm_86's ruleset gives no form for (`err word_div`). 66 are calls or elements cu.krs gives no form for, 30 atomics and 34 statements.
- **The run channel.** A question carries as many cases as a launch gives threads, up to the 2^20 the host fills, and the run tool gives every case a thread. Every ask of the protocol puts all 648 cases the host computes: the register walk holds each probe to every one of them and reads the last register R252 over 35 asks, 9 alike, 20 refused and 6 held by the gate (`KLQ_TRACE` writes each ask and its answer).
- **The slices.** A context no two questions of the host hold is asked of nothing: 762 of 1113.
- **Two words.** A 64-bit form is put as two forms of 32 bits as NVIDIA's listing writes it, and the width that would ask it is Step 1, theory.
- **The walks.** The register walk starts below the top of the field, 255, and the threads stop at the 2^20 the host fills cases for (Step 9).

**Step 9. The part's numbers, walked until it says no.** These relations are over a number n and not a word. Each holds below a bound and is refused past it:

  holds(n) ⇒ holds(m) for every m < n

and the walk reads one bound, the greatest n that holds.

- **The last register.** `holds(R_n) ?`: a chain register written and read back, renamed R_n, in a kernel declaring 255, and the control renames it to the least number nothing uses. The walk goes down from the top of the field below RZ, the name the field's top gives the register that reads 0. n = 254 and 253 are refused as illegal instructions, and 252 is alike: last = 252. **Measured** on the RTX 3070, sm_86 (`klq_identity register`, kept in `sm_86.ksc` as `run answers 000000fc register last`).
- **The launch.** `run(r, t) ?`: t threads a block, doubled from 1, with r registers declared. The part refuses past a bound at each t, and the walk reads it: on sm_86, task 1006 answers at every count of registers the walk put, up to 255, in blocks of up to 256 threads, at 128 and is refused as out of resources at 129 in blocks of 512, at 64 and is refused at 65 in blocks of 1024, and a block of 2048 threads is refused as an invalid value at every count (`klq_identity curve`, `curve.txt`). That bound is the part's answer and is written nowhere. The host bounds only the threads it fills cases for, 2^20 in all (`CUBIN_RUN_THREADS_MOST`, `cubin_run.c`). **Measured.**
- **The soonest read.** `alike(w, s) ?`: a chain where writer w's result is read by the very next link, every stall the longest and w's stall s. The stall runs the other way, holds(s) ⇒ holds(t) for every t > s, and holds at 0 on every pair the part answers: stall 0 is no zero cycles. Every stall from 0 to 15 of every pair is put in one round on up to three probes, and the soonest is the least s from which every longer stall answers alike. **Measured** on sm_86 (`pairs stall`, kept in `sm_86.ksc` as `run answers <s> stall <writer> <reader>`): integer, logic, compare and select pairs 4; `IMAD` into `LOP3.LUT`, `PRMT` and `SHF.R.S32.HI` 5; `IMAD.WIDE.U32` into `IADD3` 5 and into a load 3; `ISETP.GE.U32.AND` into `EXIT` 13; `IMAD.WIDE.U32` into `STG.E.64` and `IMAD` into `ISETP.GE.U32.AND` alike at every stall. A pair no chain of ours holds is probed in the arrangements of the `.kdm` that hold it, written at their operator's link: both rotates, `SHF.L.W.U32.HI` and `SHF.R.W.U32`, 4.
- **The fewest registers.** `alike(T, r) ?`: task T run with r registers declared. r is walked up from the count of registers the chain names until alike, and halved down until not, at one thread a block. A container declaring d gives code R0 to R(d − 3), as the last register gives at d = 255. **Measured** on sm_86: chains naming up to R21, R69 and R197 are refused at 22, 70 and 198 declared, and answer at 24, 72 and 200. A chain naming up to R13 answers at 8 and at 1: under some count the part gives a container more than it declares.

**Step 10. The cost of a task, by the bounced sustain.** c(r, t) is task T's cost on the part's clock, read over 100 launches, at r registers and t threads. The ask is

  `c(r, t) ≤ hi ?`

against a band B = [lo, hi] read at the fewest registers:

- An ask inside B sustains it. B holds after 5 asks in a row land inside it without widening it.
- An ask past B is falsy only where it lands past B twice with the baseline asked between them landing inside B. Where the baseline strays, B widens to hold it and the count starts again.
- knee(t) = the least r with c(r, t) past B, found by bisection over r, which reads one bound where c(·, t) past B holds of every r above it.
- Each t is walked, doubled from 1 until the launch is refused (Step 9), and the curve of a task is its knees against t. **Measured** on task 1006 at one thread: 1.80 ms up to r = 128, 2.11 ms at r = 129, 3.04 ms at r = 192.

**Step 11. The ruleset.** For each slot σ the survivors S(σ) of Steps 2 to 7 are ranked by P6, and the slot is given c_1 where m_c2 − m_c1 > s and keeps its form where not. Steps 1, 9 and 10 give the part's numbers: the width, the last register, the bound on a launch, and each task's knees. Each is kept with the part and the size it was read on (Q10), in the part's `.ksc`.

### P12. Categories, and the coherence set C* (P10, P11)

### P13. The sets, open-ended, and what they collapse (P2, P5, P10, P11, P12)

Every set below is open. No set is known whole (P10), and an entry added is asked as the others are.

- **The categories.** C* = ⋃_c c, and a category is a pair c = (asked, answerer). The asked side is gnascor's thing and doing words, the tables of [gnascor.md](../../../src/cu/transpiler/gnascor.md), and the sets of our coherence below, which those tables file among their thing, doing and gluing words. Each such set is named `<n>_coherence`, its stem what it holds. The answerer side is one of the kinds below. Each category has a clear operational line, and where two categories blur, the blur is another category.
- **The tree.** The sets are nodes of one tree of linked nodes. Each node is one equality test, and each set is the node of everything beneath it, a set of sets where it holds others. A node with more than two members is a binary tree in the first-child, next-sibling form: the first link goes down into the set, and the next goes to the member beside it. A sibling link between two members is their negation. A fact one node holds and several parents read, the statement, is one node linked from each, and its answer is written there once. A fact of more than one part is a set of its own, each part a member: a set that holds two kinds of thing is a clump, and it splits into a set for each. A set needs no name: its relation is its identity, the concept below. The metas are internal nodes: each says why an entry sits where it does, a pair hangs from every meta its tests read, and each is written above the set the pair is read into. The sets are our coherence, and a language is read through them by its relational map to them alone. `unknown_coherence` ends every set: an entry no answer has read further down stays there, a member of every set beneath. - **When a language is read.** A language is read through our coherence where its program builds: written from the rules the query has read, it answers alike with the host on every case. `unknown_coherence` empty at every node the program's path passes is the same condition. Where the program does not build, either the question was malformed, the part refusing the ask as it was written, or an entry the program needs is still in `unknown_coherence`, and the query runs another cycle. L* stays open: no set is known whole (P10), a language added brings its entries in at `unknown_coherence`, and a program built closes the path it reads and no other.
- **Every cycle ends.** A cycle ends in one of three ways, and each is bounded. An entry moves down a node, and a path of the tree is finite. A question comes back malformed, refused, nothing or held, and its path stops with the part's reason. A built program answers apart at a case, and that case moves an entry: R holds every ask, and no ask is put twice. The cases K_c grow to test our coherence, each added by the descent (Collapse 4), and a run grows only by the cases added. Where a program does not build, the query says which of the three stopped its path: the question to put otherwise, the node still in `unknown_coherence` to ask next, or the case and the link the program answered apart at.
- **Folding.** `folding_coherence` is internal: our coherence held against itself. Where the tests grow past what the cycles settle, the tree is read for tests that answer one another, and each is factored out and asked once. One ask at a node answers both members a sibling link joins, its negation the other. `lt` answers `gt` across the swap. The statement is asked once at its node, and every parent linking it reads that answer. `zero` is `eq` at 0. What folds is the testing across nodes, and no entry and no answer is lost to it. The decoder writes `folding_coherence` above every pair whose concept another pair shares: one ask answers both.
- **Every set.** Our coherence is these sets, `equality_coherence` the root of all of them. The decoder writes `qualifier_coherence`, `modifier_coherence`, `statement_coherence`, `negation_coherence`, `witness_coherence` and `unknown_coherence` as the sets a pair's answers read it into, and `comparison_coherence`, `equality_coherence`, `order_coherence`, `operation_coherence`, `commutative_coherence`, `verb_coherence`, `range_coherence`, `vector_coherence`, `control_coherence` and `switch_coherence` as the categories its two texts read it into before any ask, all beneath its verdict in the order of the tree. `concept_coherence <hash>` and `intent_coherence <value>...` come beneath them, and `structural_coherence`, `syntactic_coherence`, `pragmatic_coherence`, `data_quality_coherence`, `noise_coherence` and `folding_coherence` above them as its metas. A text settles nothing: a pair the texts read into a category and no answer reads into a set is in that category's `unknown_coherence`, and is written with both. `timing_coherence` is named, with its line below, and no test writes it yet: its tests are the timed asks. A set grown from answers and named by no word is held by its concept. An entry is a member of every set and every meta a test reads it into, each membership a light of its own on the switchboard: a pair read into two sets is written beneath both, never folded into `unknown_coherence`, and is in that set only where no test reads it into any.
- **The concepts.** `concept_coherence` holds the concepts, each a product: whether the two forms write one value or two on each case, as a function of the values the form reads there, alike, apart or both at each combination of them, written beneath the pair as `concept_coherence <hash>` (`concept_product.h`). The values are the part's own, read at the form: the carrier is cut just before the form for each value it reads, and just after it for each form's product, and the value stored in place of its answer. A concept cares for nothing that made it. The links of a carrier before the form and after it are deltas of their own, and a product read through any carrier is the same where the values are those the cases are made of. A product is a concept once it is whole, a row at every combination of those values, a register and its `.hi` one wide value: a part of a product is not yet any one concept, and the query puts the pair on past its first case apart, at each link that reads the form in a shape no link read before, until the product is whole or every branch is put or steered off. The links are walked in bands of one delta, the nearest first, and each band is a steer: truthy where a put in it adds a row that came back one way, signal, and falsy where its puts add none or only rows that came back both ways, noise. A truthy band steers on to the next, and a falsy band past the first case apart steers off every farther one. The cycle loops while the product is not whole and a branch is left, and ends where it is whole, where the question is malformed, or with every branch put. A product the question's cases leave short of whole is put at each new shape over every combination of the values the cases are made of, all three operands through them, run by run. The form's reads are taken in the order it names its parameters, a parameter the chain binds to a literal read as that literal, so that every carrier of the form reads one set of values; a parameter inside `[` and `]` says where the form reads and is none of them. Two pairs of one product are one concept whatever names them and whatever language wrote them, and a word, where one is given, is a key on the identity as a language's `.klm` keys its names to the bridge. `signed_word_shr` is one such: shifting a signed word right is a concept, whatever chain holds it.
- **The rounds.** Each pair is put in a thread of its own, and the pairs take turns in the order of the bridge, each running until it asks or is put. Once every pair left has asked, the round's asks go to the part together (`run_channel_ask_many`): the mundane in one process, and each dangerous one, a stand-in that reads or writes memory through an address or sends control elsewhere, in a process of its own. A mundane ask the part refuses ends its process, its ending is its answer, and the asks after it are carried again. No ask of a round waits on another's answer, since a pair asks its next only once its last is answered, and what depends on an answer is asked in a round after it. A round is a pass, and the rounds loop while a pair is left to put. Every mode plans its questions in tiers the same way: each question that waits on no answer but the tier's before it is written before any is put, and a tier is one round. `cost` is one round, every arrangement's check and its clock and each link's clock alone (6140 questions); `stall` is two, every chain at the longest stalls, then every stall of every probe of every pair (5058 questions, 43 s with the record answering what it holds). A round is carried 1024 questions to a process, for the memory each holds while it is put. Every answer is held by its question's identity, its code, registers, shape, launches and cases, in the part's query record, `sm_86.kqr`, and an ask of an identity held is answered from there, in this cycle or any later one: the earliest identity of a chain is asked once and read from then on. The record ends with each pair and its verdict, and an open pair is the question a further pass takes up.
- **The choices.** Every choice a put makes at a link is written to the log as `choice <flags> <link>`, the flags of the trace's table (`src/cu/types/file_defs/klq/query_trace.tsv`) that hold there ORed into one word: a link nothing reads after, the carrier's own, written as it stood, not assembled, steered off, of a shape read before, alike, apart or refused, and the put's own end, a const stop, a parameter of the stand-in with no argument, a stand-in the ruleset cannot write, or a form at no link. The table is the only place a flag is named: `klq_identity` and `klq_decoder` both read it, and the decoder writes the choices of every put and, for each pair the part answered nothing of, how many of its links held each flag, the question a further pass takes up. **Measured**, seed 1, the twelve pairs asked nothing: `thread_idx_x` and `block_idx_x` stand at 441 links, every one the carrier's own, and their `y` and `z` forms and every extent at no link; `wide_pack` and `wide_from_word` at 22, all the carrier's own; `wide_mul_word_add` against `wide_mul_word` at 882 of the carrier's own and 10 the stand-in writes as they stood; and `test_wide_ne` against `test_word_nonzero` gives a parameter no argument either way round.
- **The lower witness.** A pair whose puts asked nothing either way round, neither form standing at a link that carries the cases, is put at the links of a third form: the first of the bridge's keys whose parameters name every parameter of both and that stands at such a link (`witness <form> <form> <third>` in the log). Both forms stand in at each of its links with the arguments its link gives by name, the part answers both over the cases, and the two answers are held against each other: f and g on K are two operations where f(k) ≠ g(k) for some k (P10). A pair the lower witness answered, alike or apart, is known: the decoder reads it out of `unknown_coherence` into `witness_coherence`. The first case apart closes the pair, written `closed <link> <case>-><first>/<second>`; alike on every case leaves it open with its count of cases. A link of a shape read before is passed over, and so is one whose writing reaches nothing the part answers, where both stand-ins answer as the chain did as it stood. Two forms that read nothing but the register they write answer the same at every link, and the first link left answers them. A parameter the third form's link gives no argument takes one through the pair's binding, what the other form writes in its place, and two stand-ins the binding writes as one text ask nothing. **Measured**, seed 1: ten of the twelve pairs asked nothing are put at `word_add` or `word_mul_add`, nine close and one stays open alike. `wide_pack` against `wide_from_word` is put at `word_copy`'s links through its binding, `low` the other's `from` and `high` `RZ`: at the 4 links that reach what the part answers it writes as `wide_from_word` writes, and it stays open, since only a link that gives a `high` other than `RZ` parts them. `test_wide_ne` against `test_word_nonzero` names parameters no third form gives, and no binding joins them.
- **The intents.** `intent_coherence`, a meta: our intent, imposed. We know the patterns we write in, and a value a form writes of its own says what the form is for: `MOV R12, 0x20` writes the warp's size. The carrier's own links, the thread's index, the case's index, the bound and the addresses, are read off the shape every carrier of ours has, and are intent of the same kind. The values a pair's two forms write as the ruleset gives them are written beneath it, `intent_coherence <value>...`, and each is put to the pair's product with every case value: the warp's size against a copied word agrees only where the word is 0x20, and the pair is a qualifier's, 0x20 its qualifier. A value the chain binds into a form's parameters is the chain's and enters no concept. Intent steers where the query looks and settles nothing: an entry stays in `unknown_coherence` until an answer reads it down, and since that set is a member of every set, intent imposed never poisons it.
- **The structures.** `structural_coherence`, a meta: one form is the other with a parameter bound. The two texts are read token for token, each parameter a marker, and where one writes a literal in place of a parameter of the other and every other token is the same, the two are one structure: `test_word_zero` is `test_word_eq` with its right operand `RZ`, `test_signed_word_negative` is `test_signed_word_lt` at `RZ`, `wide_from_word` is `wide_pack` with its high word `RZ`, `word_from_byte` is `word_bitand` at `0xff`. The query puts such a pair with the parameter bound, each of the stand-in's parameters given by what the form writes in its place, and writes the binding beneath the put in the log, `binds <parameter>=<literal>`.
- **The syntaxes.** `syntactic_coherence`, a meta: the two forms are two operations, their first words apart up to the first `.`, one meaning written twice. `thread_idx_x` is `S2R` and `word_copy` is `MOV`.
- **The pragmatics.** `pragmatic_coherence`, a meta: both forms read what the launch gives, a thread's or a block's number from a special register or an extent from the constant bank below the parameters, and each means what the launch makes it. Our launches have one axis and no question reads `y` or `z`: no form across axes stands at a link of its own that carries the cases, and the lower witness puts each pair at a third form's link instead, and in a launch of one axis `y` and `z` read 0 and 1. Their meaning is the launch's, and `vector_coherence` holds them once launches of more axes are put.
- **The data's quality.** `data_quality_coherence`, a meta: the pair was answered and the cases could not make its product whole, a value the product needs that no case reaches as it was loaded. `word_mul_add` against `word_mul` reads its addend off the third operand of a case, which holds two values.
- **The noise.** `noise_coherence`, a meta: a row of the product came back both alike and apart, decided by something outside the values the form reads. `thread_idx_x` against `word_copy` agrees where the word read is the lane's own index, and which case a lane holds is the carrier's. Signal is the small part and noise the large: the decoder writes, for every set, its pairs, those a whole product names, and the rows of their products that came back one way against those that came back both ways.
- **The qualifiers.** `qualifier_coherence`, a category of C*: a statement x that qualifies the result of a statement y, the condition under which y's result stands. Each is asked as y with x against y alone. On every case where x holds the two answer alike, and on a case where x fails y's result does not stand: a pair of them closes only at a case where x fails. `LDG.E.CONSTANT` against `LDG.E`, `ld.global.nc` against `ld.global` in PTX, qualifies a load by nothing writing the memory it reads while the kernel runs, and the C of both is one text. Every carrier holds that, the two answer alike and the pair stays open, and it closes only on a carrier that breaks it, which the C leaves undefined. Whether a load may be const is read off its chain, a store to the memory it reads, and once the chains are ordered each load's slice settles it. The put stops at its first link alike and the question stays open: where the rest of a chain fails, the pair is asked again for a lower identity to witness it. A flag glued to a test qualifies it the same way, `test_word_nonzero_and` against `test_word_nonzero` closing at a case where the flag fails, and so do `if` and `unless` on a doing word and `atomic`, no other thread coming between. The statement x is a condition, a flag: an operand one form names and the other does not that carries a value, the value `word_copy` copies or the addend of `word_mul_add`, is what the result is made of, and qualifies nothing.
- **The modifiers.** `modifier_coherence`, a category of C*: a word that changes what a form reads, writes or does, asked as the form with it against the form without it. Where the two differ both results stand, and a pair of them closes at its first case apart: `global_load_signed_byte` against `global_load_byte` closes at `0080:00a0`, and `signed_byte` is the thing it reads. A modifier qualifies nothing. Each pair of `Lstar.klq` whose two forms are one text but for their modifiers is an entry of `qualifier_coherence` or of `modifier_coherence`, and the case it closes at sorts it: a case where x fails is a qualifier's, and a case where both results stand is a modifier's. A pair open on every carrier is a qualifier's.
- **The vectors.** `vector_coherence`, a category of C*: a word whose answer changes with where a lane sits and the shape of its launch, and never with the case it is given: `thread`, `block`, `grid`, `idx`, `dim` and `warp`, each taken at `x`, `y` or `z`. It is asked over launch shapes and not over K. The texts read a pair into it where either form reads a thread's or a block's number or an extent, and into `pragmatic_coherence` as well where both do. Put by the lower witness at a link of `word_add` in launches of blocks of 256 threads, `block_idx_z` and `block_idx_y` answer alike on every case, both 0 in a launch of one axis, and stay open; every other pair across axes closes at its first case apart: `thread_idx_y` and `thread_idx_z` against `thread_idx_x` at the second lane, `block_idx_y` and `block_idx_z` against `block_idx_x` in the second block, `block_dim_y` and `block_dim_z` against `block_dim_x`, 1 against 256, and `grid_dim_y` and `grid_dim_z` against `grid_dim_x`, 1 against 3.
- **The ranges.** `range_coherence`, a category of C*: a part or a place, a description of range, which piece of one whole a form gives: `low`, `high`, `first`, `middle`, `last`, `left` and `right`. The parts of one whole put together give the whole, an entry of I (Collapse 3): `word_mul_low` with `word_mul_high` is `wide_mul`, and `word_add_first`, `word_add_middle` and `word_add_last` are a chain of one add. The texts read a pair into it where either form names a parameter at its `.hi`, working a wide value in its pieces, the low word first and the high after it.
- **The comparisons.** `comparison_coherence`, a category of C*: a relation between operands that gives a flag, `lt`, `le`, `gt`, `ge`, `eq`, `ne`, and against 0 `zero`, `nonzero` and `negative`. Each is tied to the others by entries of I: lt(a, b) = gt(b, a), ne = ¬eq, and `zero` is `eq` against 0. The pairs `test_word_ne` and `test_word_nonzero`, `test_word_eq` and `test_word_zero`, `test_signed_word_lt` and `test_signed_word_negative`, `test_wide_eq` and `test_wide_zero`, and `test_wide_ne` and `test_word_nonzero` are each a comparison against an operand beside the same comparison against 0. The first four are `structural_coherence`, put with the operand bound to `RZ`, and each closes at a case whose operand is not 0: `eq` against `zero` and `ne` against `nonzero` of a word are one concept. The last is a wide against a word, two lines against one, and no token reading joins them. It holds two sets, and the statement is the line between them. The texts read a pair into `comparison_coherence` where both forms set a flag by a `SETP`, into `equality_coherence` beneath it where every condition the two test is `EQ` or `NE`, and into `order_coherence` where one is `LT`, `LE`, `GT` or `GE`.
- **The equalities.** `equality_coherence`, a part of `comparison_coherence`: a distance from n of 0 or not 0, n any value, `eq` and `ne` at the other operand and `zero` and `nonzero` at 0. It needs no statement of reference: two words are equal under every reading of their bits, and gnascor's tests have no signed row for any of them. Equality is purely relational, and maps directly to the relational assembly: every verdict of the protocol is an equality over cases, alike or apart, and Collapse 1's integer case is f(k) = h(k).
- **The orders.** `order_coherence`, a part of `comparison_coherence`: `lt`, `le`, `gt` and `ge` at the other operand and `negative` at 0. Each needs a statement of reference for one thing to be less than another, a sign and a width, and no answer has given one. Its entries are `unknown_coherence` until the part reads the statement out. The statement is the delta between the two parts: `test_signed_word_lt` against `test_word_lt` is apart in the statement alone, `ISETP.LT` against `ISETP.LT.U32`, and the decoder reads the pairs apart in a statement, or across the line from an equality to an order, into `modifier_coherence`, where the statement is what moved. The floating bracket of Collapse 1 is order as well, the end the part takes its rounding.
- **The operations.** `operation_coherence`, a category of C*: a form that computes a value from its operands, a shift, an add, a multiply, a bitwise or a floating operation. An operation is one whatever its scale: a shift of a bit, of a word and of many words is a shift, and `signed_word_shr`, `word_shr`, `signed_wide_shr` and `wide_shr` are all of it. The texts read a pair into it where either form's opcode computes, `IMAD.MOV`, which moves a value, apart.
- **The commutations.** `commutative_coherence`, a category of C*: a form that gives one value with its first two sources taken either way round, an add, a multiply, a least or a most, an equality, and a bitwise table whose bits at a = 1, b = 0 and at a = 0, b = 1 agree: `LOP3.LUT` at `0xc0` is an and, and commutes. The texts read a pair into it where either form's every instruction commutes. One ask answers a form with its sources in both orders, a fold.
- **The verbs.** `verb_coherence`, a category of C*: a doing word that computes no value, tests nothing and sends control nowhere, a load, a store, a move, a copy or a read of a special register. The texts read a pair into it where either form does one: `global_load_word` against `global_load_constant_word` is two loads.
- **The negations.** `negation_coherence`, a category of C*: a word that, taken twice, gives back what it was given, x(x(y)) = y on every case: `neg`, `not`, a predicate's `!`, and `unless`, which is `if` negated. On the tree a negation is the sibling link between the two members of one node, and the decoder reads it off a pair of forms of a flag that name the same operands and answer apart whatever the link reads: every case apart, or apart only where words the link does not read decide it.
- **The timings.** `timing_coherence`, a category of C*: every time the part gives, held in one place. The stall is the soonest a result is read, walked down on the part (Step 9) with the barriers and the waits that hold a read until its result is back (P9). An operation's time is read off the curve of a task, its knees against the registers and the threads (Step 10). A vector's time is the delta of one step along it: the simplest asks put in orders drawn from a seed, one register, one lane or one operand of a case more, and the delta between the orders the cost of the step. No time is written in: each is read as a delta between orders or between steps, and a time no answer has given is `unknown_coherence`.
- **The vectors of an ask.** An ask enters the part through its vectors, a register, an address, a lane: the registers it declares, the operands of a case its code loads, and the lanes it is put over, a case a lane. Its magnitude is how much of each it takes. The query asks the simplest first, at the least magnitude, the registers its chain names, and walks up only where the part refuses the least and answers the most. Carriers of one magnitude are put in an order drawn from a seed, and the delta between the orders is the cost `timing_coherence` holds.
- **The controls.** `control_coherence`, a category of C*: what decides which form runs next, in its parts. The transfer is what is done, `exit`, `return`, a branch; the loop is the way back and the label it goes back to; the condition is what it is done under, `if` and `unless`, one node that the qualifiers' guard links to, since a guard qualifies a result and conditions a transfer; the target is where it goes, a `label`; and the dispatch is a state's next, `state_dispatch` and `state_next` where a target clocks a lane a state at a time. The texts read a pair into it where either form exits, returns, branches, calls or sets a convergence.
- **The switches.** `switch_coherence`, a category of C*: a word no case reads that places the forms a case does read, `open`, `body`, `close`, `note`, `declare` and `start`. Taken out, one changes no answer or refuses the whole program, and never moves one case. The texts read a pair into it where either form holds no instruction, nothing ending at a `;`.
- **The unknowns.** `unknown_coherence`, a member of every set of our coherence: an entry no answer has read into a set. It can be anything, and it is therefore a member of all of them until an answer reads it into one. It is the gray of P1. A pair of `Lstar.klq` the decoder reads into no set is written `unknown_coherence` beneath its verdict.
- **The cases.** K_c for each category, grown by the descent (Collapse 4).
- **The identities.** I, relations between texts. Each is witnessed by the text, and both its sides are held to each other on the part over K (P10). Each is an entry of `Lstar.klq`, `text_identity <text> = <text>`, its sides functions as the stick's manifest writes them, and its verdict beneath it: closed at the first case the host or the part answers its sides apart, open with its count of cases where both answer them alike on every case. A name of the bridge carries its stem and then what it is, an identity or an address: the identities a slice of two questions carries are `slice_identity <address>`.
- **The compositions.** Chains of forms, a category whose cases are its links' cases (Q19).
- **The record.** R, every ask with its answer, the part and the size it was read on (Q9, Q10). An ask R holds is not put again. Its rows sit in the part's `.ksc` (`ksc.oracle.tsv`), each keyed by the hashes of its code, its cases and the host's answers to them, and the registers and shape it is put with. Its word is the host's place of the first case apart, `ffffffff` where every case is alike. A timed ask is a sample of its own and put every time, and an ask the gate holds never reaches the part and has no row.

**Collapse 1. One relation for every exact answer.** The host gives an exact value bracketed at the result's width w, and every ask of it is f(k) ∈ [down(k), up(k)]. **The scheduler.** The gray entries of every set are its queue, and P11's bounds are that queue written out. Each turn:

### P14. A system learned, and the writers that read it (P8, P9, P11, Step 9)

**The goal. The query protocol learns a system by asking it, and holds nothing about that system it did not ask.** Every fact a ruleset or a machine file states of a part is the part's answer to an ask: the forms it holds, what each answers, where each form's operands lie, and when a result can be read. The protocol is the interface from the transpiler to any system. It is the same for every system, and nothing in it names a vendor.

**The split.**

- **The protocol asks.** Its code is `src/cu/transpiler/lstar`. The slot, the relations over the cases, the fields of each form, widening and the part's scheduler are all asks, and each answer is written to R and to the part's files.
- **A vendor's writer reads.** Its code is `src/cu/transpiler/vendor_bin_layouts/<vendor>`. It takes what the protocol learned and writes it in the vendor's container and vocabulary: the container the system accepted, the file a part's forms are kept in, and the names its compiler prints (`elf64_nvidia.tsv`, `mnemonic_nvidia.tsv`). Each writer is a thin switch or a table it picks from, and it asks nothing.
- **A fact a writer holds that the protocol can ask is a value written by hand (P11)**, and it moves to the protocol as an ask.

**The part's scheduler is learned, and has nothing to do with writing.** When a result can be read, what holds an instruction back until then, and for how long, are facts of the part. Its timing is part of the system being learned as much as its forms are (`timing_coherence`).

- It is asked as P9 and Step 9 ask the soonest read: an ask over forms the part has already answered, each answer kept in R and in the part's `.ksc`.
- The places in an instruction the part's scheduler reads are asked as the places of a form's operands are, and kept in the machine file beside them. So are the instruction's size and where its operation key lies. No constant names any of them.
- Every ask that learns the scheduler holds to P9's bound. It is checked against what the part has already answered before it is put, and an ask that could hold a wait the part never releases is not put.
- The gate (`cubin_safe`) holds a question to what the part has answered of its scheduler. Where the part has answered nothing, it holds it to the scheduler as the kernel the system accepted holds it.

**What is to do.**

1. `khw_write.c` (`src/cu/transpiler/lstar/parser`) asks the part where its scheduler and its operation key lie, and keeps each answer in the machine file. It reads none of `SASS_STALL_FIRST`, `SASS_WAIT_FIRST`, `SASS_WRITE_BARRIER_FIRST`, `SASS_READ_BARRIER_FIRST`, `SASS_STALL_LONGEST`, `SASS_WAIT_EVERY`, `SASS_BARRIER_NONE` or `SASS_OPERATION_MASK` (`sass_machine.h`), and none of the instruction's size.
2. Reading the kernel, its endings and its registers out of the container, keeping a form and writing the `.khw`, and composing a form's name from the vendor's table move from `khw_write.c` to `vendor_bin_layouts/nvidia`, each a picker over what the protocol learned.
3. `klq_identity.cu` (`src/cu/transpiler/lstar/protocol`) splits the same way: its asks stay in the protocol, and every `sass_*` and `cubin_*` call it makes moves behind a vendor's writer.
4. `cubin_safe` reads its rules on the scheduler from the part's answers in the machine file and the `.ksc`.

- **Theory.** Nothing of P14 is built.

## The protocol

**the query protocol** is the form every ask takes, and it is what derivation is made of. A question put to a target is an address, a qualifier and a cost bound:

    [ ADDRESS ] -> ( QUALIFIER ) -> [ MEASURED COST ] -> BINARY RESULT (1 or 0)

The address names the target: a memory address, a URI, an API endpoint, an LLM context key, a register. The qualifier is a binary question asked at it, phrased to demand a state validation and never a data payload. One loop can therefore ask a part and a service the same question. The cost bound is the most the target may spend to answer, and no hand writes that field.

**The bound is unbound first.** An ask carrying no bound returns the cost instead of a bit: a measurement, never a verdict. The spread of those costs is the baseline, and the baseline is `.knf`. Every bound after that is expressed against it. No absolute figure is ever written into the machine. Binding a query to `$10ms` by hand is a scale written into the machine, which the engine is optimized against at every other point; the unbound pass derives the figure in place of choosing it.

So the protocol is two passes of one ask. The unbound pass returns a cost and tells us where to go: a cheap address is worth expanding and an expensive one is worth chaining or pruning. The bound pass returns the bit, and the bit is what a branch consumes. A missing address, a false qualifier, a timeout, an error and too many cycles all read 0 at that point, and the distinction between them survives in the baseline instead of in the bit.

Two things the unbound pass has to record. A watchdog stop is not a cost reading, it is a censored sample, and a baseline built without marking them reads low. And a baseline taken once goes stale the moment the host's load changes. The reference ask is therefore put alongside the real one and measured in the same conditions, the same way the emission order is shuffled to leave nothing to tell measurement from work by.

**The baseline buys chain slicing.** A chain carries a cost and one number for a whole chain names no part of it. Put the unbound ask at many cuts of the chain and the per-link costs come out of the readings together, each one measured in the same conditions as the rest. A chain is then a profile and not a total, and the expensive link is named instead of inferred.

How the asks are ordered decides whether that works at all, and the arithmetic is measured in `utils/maint/engine/measure_check.py`. Subtracting neighboring cuts puts the noise of two measurements on a quantity the size of one link, and one link is the quantity sitting under the floor: the recovered cost carries 1 + 12543/12800 floors squared of noise against a signal of 1, which orders 56 + 9692/41993% of link pairs correctly where a coin orders 50%. Repetition, descended level by level, still orders more pairs at 6400 repeats of every cut, 97 + 143/181%, and the order of asking fixes it for far less than that.

**The emission order is not a shuffle, it is a carrier.** A shuffle throws away what it scrambled. This order is known to the asker and tells the part nothing: the part has no way to separate a measurement from work, and every answer is still decodable, because the order is in the record. Build it so every ask covers half the links and any two asks overlap on a quarter, and the answers come apart exactly. One ask then informs every link at once in place of one link. The squared gain over asking a link at a time is (links + 1) over four: 1 + 15541/35219 at 3 links, 4 + 31188/189499 at 15, 60.2291 + r/d at 255, and growing with the chain. Nothing beats the bound on what one answer can carry. A known order reaches that bound and asking one at a time does not, and the whole gain is that difference.

A known order also beats a drawn one, and by more the further out the reading is: 4 + 883/1053 times at the median worst-link error, 31 + 37/135 at the 95th, 145 + 5/6 at the worst of 400. 18 of 400 drawn orders do not come apart at all and cost their whole pass. An engine answering every time is held to its worst case, and a known order has the same worst case every pass by construction.

**Where links contend the costs stop adding, and the solve does not say so.** It returns plausible per-link numbers with the contention folded into them, and what the fit could not account for stays flat while the answers go wrong by a factor of two. What catches it is a term for contention's own shape. Contention grows as the square of how many links an ask covers and the links themselves grow as the count. An order sweeping that count therefore separates the two, and an order holding it at half gives the difference nowhere to appear. The term notices at 88% where the leftover notices none of it, and the same solve then takes the damage back out. It costs one more unknown and not one more ask.

Cross-branch comparison follows from that, and it is the reason the arrangements are all kept. Every arrangement that produces an operator is a branch, each branch slices into the same relation, and comparing them link by link gives the winning path for a given problem instead of one arrangement that suits nothing in particular. A chain reading worse as a total can hold the cheapest link for the job, and only a sliced reading can see it.

The rest of the protocol, the pair states and the mnemonics the bits resolve to, is in [gnascor.md](../../../src/cu/transpiler/gnascor.md). Every step of it, what backs it and the run behind its status is in the table above, and a step changes status there and nowhere else.

**The gate is the engine's own descent.** Each candidate arrangement is an alignment and a relation's cases are the needle, and orior's descent places the case that prunes the most, stops where the best case prunes nothing, and leaves the survivors as its answer. The descent is planned on the host against arithmetic every system that computes agrees about, and a target is asked only the cases it placed. That is steering on what is known to be true. Survival is a conjunction, and order cannot change a conjunction. A plan that steers badly costs speed and never a wrong survivor: gate then rank, in the engine's own words.

Cost is measured by chaining, never alone: one operation sits under the noise floor and a chain clears it by fifteen times. Chaining is also what takes the bias out. A primitive that reads worse by itself and is right for a job is then chosen for that job.

An operator is a chain of primitives and the chain can be rearranged. Every arrangement that produces the operator is kept with its cost, and a job takes the one that suits it, in place of one arrangement that suits nothing in particular. A person writing a compiler by hand affords one arrangement for each operator, because a person has to write it. Nobody writes these, and the best for an application is therefore always available.

## The run, a database (Q20)

**A run is one table of blobs, and is to be a database of its own, a table for each area of it.** A run's `.qry` holds every blob handed to it and a table of them, a row a blob: its name's hash, its sequence, its time, its priority and where its bytes sit (`qry.h`). Each process of the run hands into a ring of its own, which the writer moves into the run in turn; a file handed to the run is written in its place once the run ends (`qry_filed`), and while the run runs every file is read from memory (`qry_file_read`). A `.kqr` a run keeps is a view of the run's table of asks, a row each record (`kqr_tabled_by`). The run as planned:

- **A table for each area.** The teacher's asks, the carrier's launches, the gate's verdicts, the overseer's conferences and lessons, the cross's pairs, the writers' files and every trace each own a table. A row is fixed numbers: its key, the run's sequence; its who (`QryWho`), the source, the line, the program and the time; and the columns its table names, each a number. A text is held once, in the run's table of texts, and a row names it by its number, as a `.kqr` names its texts (`krep_records.h`). A table's columns and codes stand in its oracle, `<area>.oracle.tsv`, and its reader and the decoder read them from there.
- **The tables.** Past the key and the who, each row holds these columns, every one a number, a text by its number and bytes of a length a row cannot fix by the key of their blob:
  - texts: the text's bytes, each text once for each process that numbers it.
  - blobs: the blob's name, its bytes and its priority, as the `.qry`'s table holds them (`qry.h`).
  - links: the key a link is from, the key it is to and the link's code: every relation between rows that one column cannot hold, the launches a verdict read, the accounts a conference heard, the rows a file was written from.
  - asks, the teacher's: the records `.kqr` holds, a row each (`kqr.h`). An ask its identity, the hash of its code, its registers, threads, blocks and launches, its count of cases and the hash of its cases, then its answer's code, the blob of its words and the text of its refusal; a sample its identity, its answer's code, its nanoseconds and the least and the most one launch took; a cycle, a seed and a round each its number; a pair its two forms' texts, the hash of what its put reads and its verdict's text.
  - launches, the carrier's: the ask's key, the blobs of its code and its container, the outcome's code, answered, refused, timed out or faulted, its nanoseconds, the least and the most one launch took, and the text of what the carrier said.
  - verdicts, the gate's: the ask's key, the rule's number, held or put, and the text of its reason.
  - accounts, conferences and lessons, the overseer's: an account the expert's code and the text it gave; a conference the question's key, the cause's code and its ruling's code, consensus or none, the accounts it heard its links; a lesson the conference's key, the cause's code, the text of its carrier or every carrier, and the text of the stand-in as written.
  - pairs, the cross's: the texts of its two forms, the verdict's code, closed or open, its count of cases alike and the key of the case that closed it.
  - files, the writers': the text of its path and the blob of its bytes, the rows it was written from its links.
- **A trace is rows.** Every row carries its who, the source and the line of the code that made it; an area's trace is its rows in the order of their keys. A decision that makes no row of its own, an ask the gate puts past a rule, is a row of its area's table with the decision's code.
- **A buffer for each member.** Each process of a run is a member and hands its ordinary blobs into a ring of its own in the run's shared memory, at the ring's tail, with no lock another member takes (`qry_buffer.h`). The writer takes the members in turn and on a member's turn moves everything from the ring's head to its tail into the run's buffer in one go, each blob given its sequence as it goes in; a ring that holds nothing has a turn that does nothing, and the member keeps adding past what is taken. A panic and a critical blob go in at the tail as they are handed, ahead of every member. A process moves its own ring before another reads what it handed (`qry_moved`) and settles every ring once a process it started has ended (`qry_settled`).
- **One writer.** The pressure buffer drains every area's buffer into the `.qry`: panics first, then critical, then the ordinary rows in stretches, as it writes blobs. As the run ends it dumps each table's rows and its index beside the blobs, and the blobs stay a table of their own for raw bytes, a cubin or a listing.
- **Rows keyed to rows.** A row names the rows it follows from by their keys: a launch the ask it carried, a verdict the launches it read, a conference the refusals it heard, a file the rows it was written from. A question about a run is a walk over keys, and the decoder (`kdecode`) is its select: a table, a range of keys, raw or decoded.
- **Files as views.** Nothing writes a file in its place while the run runs. A file handed to the run is a row of the files table and its bytes, every program of the run reads the latest of it from the run (`qry_file_read`), and the writer writes each file in its place as the run ends. A file the run reads from the disk is taken into the run the first time it is read, and read from memory after: while the run runs, it reads from memory and not the disk. A tool outside the run that reads a file from the disk while the run runs, nvcc, nvdisasm or a script's `cmp`, is pointed at a stream the run puts out for it (`qry_streamed`), as `measuring_stick_query.c` points nvdisasm.

It is built in this order, each step held by the checks that hold the run now (`chain_check.sh`, the overseer's check, the writers' bytes):

1. A buffer for each member under the blob calls as they stand, and the time of a hand measured under contention before and after. Built and measured (`build/harness/qry/hand_time.sh`, 2000 hands of 256 bytes or 200 of 64 KiB a process): a hand of 256 bytes takes a median of 0.1 µs at 1, 4 and 16 processes against 1.2 to 1.4 µs under the one lock, and its 99th hundredth 1.4 to 2.3 µs against 5.5 to 18; a hand of 64 KiB takes a median of 31 to 41 µs against 30 to 50, its 99th hundredth 170 to 2491 µs against 56 to 341, and 16 processes hand theirs in 15.4 ms against 25.0. Every byte reaches the run as handed.
2. Files written as the run ends, and every step that reads a filed file from the disk while the run runs found and pointed at a stream. Built: the writer writes each file's latest handed bytes in its place once the `.qry` is dumped and before it says it has stopped; a file the run reads from the disk is taken into the run and read from memory after; the engine's ruleset reader reads every ruleset, `.kdm` and `.ksc` as the run holds it, a program built without the run's buffer linked to stand-ins that read the disk (`ruleset_flat.cu`); and every other read of a file the run writes, `klq_identity`'s pipe rows, the descent's cases and `sass.krs` in the scaffolding and the monolith, goes through the run. `kdm_check` holds a file the run writes to be read from the run and not the disk while the run runs, and `chain_check.sh` holds it in its place once the run has ended.
3. Rows: the head and the records of `krep_records.h` made a table of the run, the teacher's asks first, which `.kqr` holds, and `.kqr` then a view of that table. Built: a k-file a run is to write is a view of a table of the run (`krep_tabled_by`), its head a critical row whose sequence is the file's key, then a row of each text and each record it holds, and a row of every text it takes and every record put, given other words or let go after, each record's row of the who in force over it; the file written is the file its rows put together in the order the run holds them (`krep_viewed`), its rows and their numbers in `krep_records.oracle.tsv`. The teacher's R and `klq_identity`'s record are each a view of the table of asks (`kqr_tabled_by`), a text a row of the file's table as the file numbers it. `kqr_check` holds the rows to put together the record as held, every text and every record, on its own record before and after what a run puts and on the part's three records; the largest, 15023 records, is made a view in 77 ms and put together in 142 ms, the tracked one in 6.4 ms and 2.5 ms (`build/harness/kqr/table_time.sh`).
4. The carrier's launches, the gate's verdicts, the overseer, the cross and the writers, a table each, and the table of texts every table names its texts from. A row of these is handed by one call (`qry_buffer.h`): a blob of the table's name, the who's two words, then the table's columns, each a 64-bit word, in the order the table's oracle gives (`<table>.oracle.tsv` beside `qry_buffer.h`). A text's number is the 64-bit FNV-1a hash of its bytes: each process hands a text to the table of texts the first time it numbers it, so that a text two processes number stands in the table once for each, under one number. An ask's key is the sequence of its code's blob, `question<n>.bin`, which the teacher hands and the carrier reads before it puts the question. In this order:
   1. The rows and the table of texts, and the carrier's launches and the gate's verdicts (`cubin_run.c`): a launch row for every launch the carrier makes, its ask's key, its outcome's code, answered, refused, faulted or timed out, its count of timed launches, its nanoseconds, the least and the most one launch took and the text of what the carrier said; a verdict row for every question the gate reads, put or held, its ask's key, the rule's number, held or put, the byte it held at and the text of its reason. Built: `qry_buffer.h` hands a row and numbers a text, and `qry_rows_check` holds a row to its who and its columns as handed and a text to its number and its one row a process; the carrier hands a verdict row for every question its gate reads, the airlock's pop with the part taken out and the carrier live, and a launch row for every launch, the tables' columns and codes in `verdicts.oracle.tsv`, `launches.oracle.tsv` and `texts.oracle.tsv`. The overseer's check, given the real carrier and cross, holds each verdict row of the pop to be keyed to its ask, held where a rule broke and its reason a text of the table of texts, and an ask read again with the count that clears it a second row of it. A launch row is made only where a launch reaches the part, and none has yet.
   2. The overseer's accounts, conferences and lessons (`overseer.c`). Built: every account the overseer hears is a row of the run's accounts, its expert's text, its own text and the cause it reads; every conference it holds a row of its conferences, its ruling, the accounts it heard, the lesson where one was taught and its words; and every lesson it teaches a row of its lessons, its cause, its carrier and the stand-in as written (`accounts.oracle.tsv`, `conferences.oracle.tsv`, `lessons.oracle.tsv`). The overseer knows a question by its identity and not by its code's blob, and each row names its conference by the identity's number in the table of texts. The overseer's check holds a conference's row, each of its seven accounts' rows and its lesson's row to its ruling.
   3. The cross's pairs (`klq_identity.cu`), the writers' files (`qry_filed_by`), and the links between rows. Built: every pair the pair mode keeps is a row of the run's pairs, its two forms' texts, closed or open, its count of cases alike, the case that closed it, the hash of what its put reads and its verdict's text (`pairs.oracle.tsv`); every file written is a row of the run's files, handed critical after its bytes in place of the blob that followed them, its who, its bytes' blob and its path (`files.oracle.tsv`); and a k-file written as a view of its table has its bytes' blob linked to the head row of its rows, the one link a column of a row cannot hold so far (`links.oracle.tsv`). `who_check` holds a file's row to its who, its sequence and its path, and `kqr_check` holds the link. No pair row has been made: the pair mode has not run since.
5. `kdecode` reading the tables. Built: `kdecode --table <table> <run.qry>` reads every blob of the run in the order of their sequences (`qry_file_each`) and gives the rows of the table from `--from` through `--to`, `--count` of them at most: raw, a line of each row's key and its words in hex; decoded, a line of its key, the row's kind and each column as its oracle gives it, a key with its blob's name, a text by its number and its bytes, a code by its name in the oracle or in the oracle its gloss names, and the who named. The table of texts is given as its texts; a table with no oracle is a k-file's where the run holds its head, each row its change as `krep_records.oracle.tsv` names it and a record put named through its format's oracle, and is given raw where the run holds none. As the run ends, the writer puts into it the oracle of every table it holds, read from the tree where the run holds none of the oracle's name: a table of the run's own its `<table>.oracle.tsv` beside `qry_buffer.h`, and a k-file's table `krep_records.oracle.tsv` and its kind's oracle (`qry_write_until_stopped`). An oracle a program of the run handed as a current file stands in the run, and is written in its place. `kdecode` reads an oracle as the run holds it, the latest blob of its name, and from the tree where the run holds none. `kdecode_check.sh`, run by `chain_check.sh` on the run the checks of R, the who and the rows wrote, holds the select to what the run holds and the run decoded through its own oracles with no tree to read one from (12 checks).

## The query, a crate

**The run's lifecycle and every loop of the protocol are one Rust crate.** The writer, the carrier, the cross and the teacher stay the C programs they are: the run is a database of processes, a carrier's fault takes its process alone, and one writer owns the buffer. The crate holds starting, joining, carrying into, reading, leaving, stopping and keeping a run; building each program when its sources are newer; and the order each loop runs its programs in, with the words it gives them. The crate is `orior-query` at `src/ui/query`, library `orior_query`, the same edition, license and Rust version as `orior-cli`, no dependency but the standard library. `orior-cli` depends on it and it depends on nothing of `orior-cli`: the crate gives a plain list of its commands, each its id, title, what it is for, its params and the words that run it, and the command line's catalog makes a job of each whose one step runs orior itself with those words, which the window runs and streams as it runs any job. The terminal runs the same code in its own process.

**The modules.** Each is one thing:

| module | holds |
|---|---|
| `run` | a query run: its folder, its `.qry`, its writer's process, whether it was joined, and the files it read and may leave |
| `writer` | the writer's words as functions over its process: `start`, `ready`, `stop`, `runs`, `hand`, `latest`, `read`, `first`, `current`, `file`, `left`, `carry`, `tee`, `who` (`qry_writer.c`) |
| `programs` | the trait the crate names the programs it needs through, by role: the C compiler, the C++ compiler, `nvcc` with `nvdisasm` and `cuobjdump` beside it, `cl` for nvcc's host compiler on Windows, `python`; and the PATH every program it starts runs with. The crate's own implementation finds each on the PATH alone |
| `tools` | every C program a loop runs, a row each: its name, its sources, its includes, its language and flags, how it links; built into `build/engine/<name>` where the binary is missing or a source or a header of a folder it reads is newer, objects compiled as many at once as the host has processors |
| `learn` | the part passes: discover, seed, turns, registers, rounds, dry, enumerate; the carrier's words, `--held`, `--lessons`, `--pop` and `--cross` |

**The programs it needs.** The crate names a program by its role and never by a path, through `programs`. `orior-cli` implements the trait over its toolchains: the gcc toolchain's `gcc` and `g++`, or the llvm toolchain's `clang` and `clang++`, whichever is chosen under File, Toolchains; the cuda toolchain's `nvcc` and the programs beside it; the msvc toolchain's `cl`; the python toolchain's program; and the PATH the toolchains give every job. Where no toolchain is chosen the PATH is read as the crate's own implementation reads it. A program not found is said as the toolchains say it, the tool's name and that File, Toolchains opens its install page or takes its folder, and the loop that needs it does not start. The vendor's programs are found and never built.

**The run.** `Run::started(folder)`: where `QRY` names a `.qry` whose writer runs, the run is joined; else `query<n>-<datetime>.qry` is made in the folder, `n` one past the highest there, `qry_writer start` spawned in the background and `ready` waited for. Every program a loop starts is given `QRY` and `QRY_TOP`, the rest of its environment as it was. `carried(names)`: each run of the folder newest first, `carry` of the names it still lacks, then any name no run holds handed from the disk where the file is there. `read(paths)`: each handed under its path from the top of the tree. `tee(program, name)`: a program's output passed to the sink line by line and handed as `<name>.console`, the writer's `tee` word the one that hands it, the program's output piped into it. The end, in order: `left` for each file the loop named, the leaves shown and asked, `stop` and the writer waited for, then only the newest `QRY_KEPT` runs of the folder kept, 64 where it is not set. A run started and not joined stops its writer however the loop ends. A run kept as its crystal is read back beside it through `qry_crystal` where that program is built; `qry_crystal` keeps its build against the engine in `build/qry_crystal/engine` through `src/build_engine.sh`, a build script, which stays.

**The tools.** The rows of `tools`: `qry_writer`, `cubin_run`, `measuring_stick_query`, `khw_write`, `khw_machine_write`, `sass_listing_seeds`, `krs_write`, `gsm_write`, `klq_write`, `klq_decoder`, `klq_identity`, `measuring_stick_read`, `measuring_stick_engine` and `qry_sweep`, each with its sources, includes and flags, and the file definitions every one of them links, `qry/buffer`, `krep_records`, `ktext`, `kqr/record`, `ksc` and `kdm`, one list in the table. `file_defs.sh` and `qry_run.sh` stay for the scripts that source them and are no loop of the query, the scaffolding's and the checks'.

**The leaves.** What a run leaves is every file it may write in its place: each path it read and each the loop named as left. Before the writer stops, `qry_writer current <path>` gives each as the run holds it, held against the tree's file. A file the same is passed over. A text file apart, `.khw`, `.krs`, `.klq`, `.klm`, `.md` or `.tsv`, is shown as a line diff; a record file apart, `.kqr` or `.ksc`, as its byte counts before and after. Then the ask, a file at a time: `y`, `n`, `all` or `none` at the terminal. A loop's `--leave all|none|ask` names the answer where no one is at the terminal: `ask` where the standard input is a terminal and `all` where it is not; the window's job takes `all` unless its form says `none`. A refused file is handed back as the tree holds it with the writer's `file` word before `stop`: the one writer still writes every current file, and the tree's copy comes out unchanged. Nothing of this touches the disk from Rust.

**The command line and the catalog.** `orior protocol <command> <words>` for every command above. `cli.rs` dispatches every `protocol` word into `commands::run`, the lines to the terminal and the code as its exit. The catalog's `protocol` group is read off the crate's command list, a job a command, its params the command's, its one step orior itself with the words `protocol <command> ...` filled from the form. The Protocol menu of `commands.json` lists each. The window's own binary takes the command line's words as `orior-cli` does.

**Errors.** A program's exit code is the loop's. A program not found is said by name and nothing starts. A writer that does not come ready ends the loop before any program runs. A loop that fails stops its writer and keeps only the newest runs. A job stopped from the window is ended as every job is, the whole process tree, the writer with it, the `.qry` as the writer left it. The overseer's panics and conferences stay on the C side of the channel.

**The checks.** Unit tests in the crate against trees under `build/`: a run's naming and numbering and what `kept` removes; the tools table, every source glob of every row reaching at least one file of the tree, and the staleness rule; the words of each command; the leaves, a diff shown and a refused file handed back. One test builds the real writer and starts, hands, reads and stops a run. The command line's catalog test takes the `protocol` group from the crate, and the harness runs the crate's tests with the others. No shell script drives a loop: every place in a source's comment and in this table that names a loop names its command. `build_stamp.sh` stays with the engine's build and the examples that source it, `file_defs.sh` and `qry_run.sh` with the scaffolding and the checks.

- **Built.** `cd src/ui/query && cargo test`, 51 tests, and the catalog test of `orior-cli`, the harness running both. **Measured**, `learn turns` on sm_86: a round of 8184 questions, airlock 6.0 s (pop 1.0 s, cross 4.6 s), carrier 2.2 s; the carrier 7342 questions in 115 readings, 5424 distinct slot encodings.

## The frame asked (Open 6.3)

**The two lines of a SASS ruleset's head are the part's answers.** `toolchain cubin_write` says what turns the text into a program the part loads, and `header container` where the text's opening lines come from. Each is asked of the part on the run channel through the airlock and kept in the part's `.ksc` as a row, and `krs_write` writes the line only where the row stands.

**The kernel asked.** Both asks put the kernel the system accepted, `interface_ask`, the one every question is laid into (`elf64_nvidia.tsv`, the container rows). It loads the case's eight words, holds the ladder's relation at its slot, stores its two answer words and exits. The kernel's places come from the vendor's writer in its `kernel` mode (`khw_machine_write`), which reads them out of the container and hands them to the run as `kernel.txt`, a head of the places, the registers a thread holds and the place the least opening begins at, then one line a place; the frame asks read that blob as the teacher does and start from the whole kernel.

**The container.** The kernel's own code, laid into the container by the vendor's writer and put over the 648 cases with no host value held against it. An answer on every case means the part loaded the container, ran the kernel and returned, and writes `run answers 00000001 container returned`; the answers are kept as the kernel's own. Refused, nothing or held writes nothing, and the toolchain stays unanswered.

**The least opening.** The kernel's places before its closing are its opening. A variant drops the kernel's first k places and puts what is left, held to the whole kernel's own answers case by case; dropping fewer always holds, holds(k) ⇒ holds(j) for every j < k, and the walk reads the greatest k that still answers every case as the whole kernel does, by Step 9's halving between 0 and the kernel's count of places, a variant refused, apart or held by the gate being falsy. The answer is `run answers <k> opening least`: the place the least opening begins at, 0 where every place is needed. Each variant and its verdict is a line of the run's blob `frame.txt`.

**Where.** One mode of `klq_identity`, `frame` (`identity/frame.cu`), first in the pair run's opening before the register walk, each row written and its record closed before the next, and on its own as `orior protocol pairs frame`. The query crate's pairs loop runs the vendor writer's `kernel` mode into the run before `klq_identity`. Every ask goes into R as every mode's does.

**What reads the rows.**

- `krs_write` writes `toolchain cubin_write` where `container returned` stands and `header container` where `opening least` stands, leaves a line out where its row is missing, and says which fact the part has not answered. The reader refuses a ruleset without the two: `sass.krs` is written from a live run's rows and committed with them.
- The vendor writer's `kernel` mode hands every place and names the place `opening least` gives where the part's `.ksc` beside the machine file holds the row, 0 where it does not, and the teacher keeps the places from there: every question it puts after is as lean as the part allows, and the gate reads the places it hands. The frame asks themselves start from the whole kernel.
- The engine's SASS writing takes the opening a listing carries, the one the vendor writer hands.

**The checks.** `frame_check` beside the protocol's checks, built and run by `chain_check.sh`: the walk over a counted `holds`; the two rows written and read back as `krs_write` reads them; `krs_write`'s head from a `.ksc` with both rows, with one and with none; the kernel handed from k. Dry: `orior protocol pairs frame --dry` through the airlock exits 0 with its dry record, and `pairs pair --dry` still exits 0 with frame in its opening. Live on sm_86: the two rows in `sm_86.ksc`, `sass.krs` written from them by `orior protocol write krs`, both committed.

- **Built.** `frame_check`, 18 checks, under `chain_check.sh`; the frame mode first in the pair run and as `orior protocol pairs frame`. **Measured** on sm_86: the container returned over 648 cases, and the least opening begins at place 1 of the kernel's 32, the place before it a load the kernel never reads, over 6 asks.

## The fixed registers asked (Open 6.2)

**Four of the fourteen fixed registers are what the kernel the system accepted leaves at its slot, and each is the part's answer.** `zero`, the register that reads 0 whatever is written to it; `lane_number`, the lane's number; `record`, the address the lane's answer is stored at; and `index`, the address its case's words are read from. The ten others, `carry`, `body`, `bodies`, `tables`, `threads`, `sign_base`, `indexed`, `one`, `ok` and `launch`, the frame never sets and no row names; each is placed by the banks' asks.

**The slot.** Each place after the opening's beginning is put with the encoding the kernel's unreached places hold; the place whose kernel then answers the case's second word on every case is the slot, nothing having written the register the kernel stores. `run answers <s> slot place`.

**Zero.** The slot's own instruction is put writing the top of the register field, that place alone changed, and the kernel's own closing stores, which read that register, read it back in the record's second word. The register the kernel stores is then left as the slot found it, the case's second word, and the top reads 0 where the record is that word alone on every case, whatever the slot wrote: `run answers <n> fixed zero`. No other register is asked for it: a question changes one place no form of the machine holds, the gate's bound (`cubin_safe.h`: one instruction at most is held by no form), and the kernel's closing store, an exact form of the machine, is held by no form once changed.

**What each register holds at the slot.** For each register n the kernel holds, the slot's instruction is put with n as its first source and zero as its second, and the stored answer is n's value, over the 648 cases, case t on thread t. The readings are held against the host's thread number: equal to t on every case, the lane's number; stepping 16 a thread, the record's low word, and the register pair it begins the record; stepping 32, the index; equal to the case's first or second word, where the words are left; 0 or one constant on every case, nothing fixed. Rows `run answers <n> fixed lane_number`, `fixed record`, `fixed index`, `case word 0` and `case word 1`. A fixed register no register holds at the slot gets no row. Each register's reading is a line of the run's blob `fixed.txt`. The register field's bounds come from the `.ksc`'s field rows, `rd`, `ra` and `rb`, as the register walk takes them, and the stall field beside them: the place a variant changes is put with its stall the longest and its yield bit clear, the scheduling the gate lets an instruction no form holds through with and the vendor's reader takes, as the walks' chains are put.

**Where.** One mode of `klq_identity`, `fixed` (`identity/fixed.cu`), after `frame` in the pair run's opening and on its own as `orior protocol pairs fixed`. It reads the kernel whole from the run's `kernel.txt` as `frame` does, and every ask goes through the airlock and into R. Dry, it says so, writes nothing and exits 0.

**What reads the rows.**

- `krs_write` writes each fixed line from its row, `fixed <name> = R<n>`, and `RZ` for the register that reads 0, the vendor's name for the field's top. A fixed register with no row is left out and named, as the head's two lines are.
